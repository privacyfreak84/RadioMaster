# PROJECT_REFERENCE.md — RadioMaster (lofi.py)

Read this once per session to know how the app is built and what rules to follow before touching code. See PROJECT_STATUS.md for what's currently in progress.

## What this is
A single-file (`lofi.py`, ~4750 lines) curses TUI for browsing/playing internet radio stations, backed by `mpv`. No framework, no packages beyond the Python 3 standard library. Runs with `python3 lofi.py`.

## Runtime dependencies
- Python 3 stdlib only. `tomllib` (3.11+) is used for TOML theme parsing; if unavailable, the app falls back to legacy single-file JSON theme overrides and never scans/writes the TOML theme directory.
- `mpv` binary must be on `PATH`. If it's missing, `MPVRemote.mpv_available` flips to `False` and the app is expected to keep running (playback just doesn't work) rather than crash.

## On-disk files the app owns
- `~/.lofi_cli.json` — main config (`ConfigManager`): stations, folders, history, volume, last station, etc.
- `~/.lofi_cli.log` — debug log (`log_debug()`), capped in-memory ring buffer of the last 50 lines is also kept for an in-app debug view.
- `~/.lofi_cli_themes/` — TOML theme directory (default). Individual `.toml` files, one per theme, with `extends` inheritance.
- `~/.lofi_cli_themes.json` — legacy single-file JSON theme format, still read for migration/fallback.
- `/tmp/lofi_cli_mpv_<pid>.sock` — per-process mpv IPC socket, created and torn down each run.

## Core subsystems

### Playback — `MPVRemote`
- Spawns `mpv --no-video --idle --no-terminal --input-ipc-server=<socket>` as a subprocess and talks to it exclusively over the **JSON IPC socket**, never over stdin. (There's a deliberate note in the code: mpv does not execute slave-mode text commands written to a bare stdin pipe unless explicitly told to treat stdin as a command source — this bit the project before, hence IPC-only.)
- `_pipe_reader` threads forward mpv's own stdout/stderr into the shared debug log, so a failed stream shows *why* it failed instead of silently doing nothing.
- `_event_reader` is a daemon thread that listens to mpv's IPC events (`start-file`, `playback-restart`, `end-file`, etc.) and maintains `playback_state` (`idle` / `resolving` / `playing` / `error`) as ground truth. This replaced an earlier version that assumed playback succeeded the instant a `loadfile` command was *sent* — which produced a permanent false "Streaming" status when a stream silently failed to resolve.

### Theming — TOML theme engine
This is the app's biggest subsystem, built up over several sessions. Full history/rationale in "Theme engine build history" below; this section is the current-state reference.

- **Discovery & storage.** Themes are one `.toml` file each in a directory — `~/.lofi_cli_themes/` by default, or `cfg['theme_dir']` if set (configurable in-app via Tools menu, no config-file editing needed; `reload_theme_registry()` re-scans immediately, no restart). `BUILTIN_THEMES` (Python dicts, hardcoded: `classic`, `retro_radio`, `cream`, `cendre`, `reference`) always exist underneath whatever's on disk. A legacy single-file `~/.lofi_cli_themes.json` is auto-migrated into individual `.toml` files on startup (archived to `.json.migrated` only once *every* theme in it converts successfully — partial failure leaves the original alone and retries next launch).
- **`extends` inheritance** (`resolve_theme`, `load_theme_registry`) works over the whole merged registry — a user TOML file can extend another user TOML file, a builtin, or a chain of either; cycle detection and unknown-parent handling both fall back to `classic` rather than crashing or hanging.
- **Serialization**: `theme_to_toml()` is a small hand-written TOML serializer (no `tomli_w` dependency — `tomllib`, stdlib since 3.11, is read-only) — deliberately narrow, only handles the shapes this schema actually produces (scalars, lists, one level of nested tables, glyph fallback-chain dicts).
- **Validator with auto-fix** — Tools menu → Validate Theme Files. `validate_theme_directory` / `validate_theme_dict` / `autofix_theme_dict` produce structured `ThemeIssue` objects (severity `error`/`warning`/`info`, path, message, optional autofix) surfaced in an in-app UI (`draw_theme_validator`, `draw_theme_validator_detail`). Checks: unknown keys (Levenshtein "did you mean X?"), bad enum values, wrong types, `extends` pointing nowhere, files that don't parse, **the "misplaced key" TOML gotcha** (see below), and info-level notes like "this theme's `idle_art` can never render given its other settings." `f` auto-fixes anywhere fixable, backing up to `<file>.bak` first.
- **The TOML "misplaced key" gotcha** — a real bug hit at least three separate times while authoring theme files by hand: a top-level key (`ascii_title`, `idle_art`, `ascii_font`, etc.) placed *after* a `[table]` header with nothing closing that table silently becomes `labels.idle_art` or `colors.ascii_title` instead of the theme's real top-level key — TOML doesn't error, it just quietly nests it one level too deep. The app falls back to its own default with no visible error, which is exactly how a theme's idle art or ASCII banner can silently just not show up. The validator now flags this specifically rather than as a generic unknown-key warning. **Anyone hand-authoring a theme TOML file should put every top-level key before the first `[table]` header, full stop.**
- **Exact hex color support** — any color slot accepts `"#rrggbb"` (or shorthand `"#rgb"`) alongside legacy `[fg, bg]` integer pairs, freely mixed. Resolution (`resolve_color_component`): if `curses.can_change_color()`, allocate a palette slot via `curses.init_color()`; otherwise nearest-256-color match (`nearest_256_color`, generated from the documented xterm cube/grayscale formula, not hand-typed). **A real, non-obvious gotcha found here**: `curses.can_change_color() == True` does **not** guarantee `curses.init_color()` actually changes anything — some terminals advertise the capability via terminfo but silently no-op the redefinition. Worse, `curses.color_content()` (the obvious way to "read back and verify") only echoes ncurses's own internal bookkeeping, not anything the terminal actually confirmed — so a readback check has **no teeth at all** against this failure mode (confirmed empirically, not assumed). The actual mitigation: allocate the palette slot whose **pre-existing default color is already closest** to the requested hex, not just the next free slot sequentially. On a terminal that genuinely honors `init_color()`, this changes nothing (still pixel-exact). On one that silently ignores it, the un-redefined slot was already the best available approximation, so the failure degrades to "close" instead of "unrelated color" (the original bug: sequential allocation from slot 16 meant a lying terminal displayed the xterm cube's blue ramp — `(0,0,0)`, `(0,0,95)`, `(0,0,135)`... — regardless of the theme's actual requested colors). `cfg['exact_color_mode']` (`auto`/`always`/`never`) is the manual escape hatch, since none of this is verifiable from inside curses. `safe_init_pair` gives every pair a **three-tier fallback** (theme's value → theme's own hardcoded default → guaranteed-safe `(-1,-1)` terminal default) — found necessary because a small enough terminal (this project's own sandbox reports `COLORS=8`) can fail to `init_pair()` even on a theme's plain default color, and the original code had only one tier.
- **Custom ASCII fonts** — `ASCII_FONTS` is a registry, not one hardcoded font; nothing downstream assumes 3×5 anymore, all layout math reads a font's own `char_width`/`char_height`. Builtins: `block` (original 3×5) and `slab` (5×5). A theme can also embed a fully custom `[ascii_font]` table (its own glyphs, not from the registry). `render_ascii_word` tries the exact input character first, only uppercasing as a fallback — so a font *can* define distinct upper/lower glyphs (case-sensitive), though `block`/`slab` don't.
- Colors are addressed through **semantic roles**, not raw color numbers — see `resolve_color_component`, and the per-aspect resolvers below.

### Theme-controlled style dimensions
Each is a resolver method on `LofiApp`, reads a theme key with a sensible default, and (except `now_playing_style`/`selection_style`, which are opt-in per theme with zero adoption pressure) doesn't change any existing builtin theme's look unless that theme explicitly sets it:
- **`density()`** — `compact`/`normal`/`spacious`. Drives `dialog_padding()` (0/1/2 rows-and-columns of interior breathing room, applied uniformly across all 11 `draw_box` callers by shifting the content-start offset, not touching per-dialog content math) and the title-to-list breathing room.
- **`now_playing_style()`** — `dense` (full metadata table, unchanged default) or `minimal` (icon/name/status only — **and explicitly, permanently no `idle_art`**, regardless of other settings).
- **`selection_style()`** — `block` (full-row highlight, default) or `marker` (▶-prefix + colored text).
- **`tab_style()`** — `numbered` (`[1]Now Playing`, default), `underlined` (quieter), or `pill` (louder: uppercase labels, wide padding, active tab a bold filled block, inactive tabs in the `label` color so the strip reads as a tab bar).
- **`header_style()`** — `plain` (default: bold accent text in the top border) or `badge` (filled block in the selection colors flanked by shaded end caps, glyph `header_cap`, default `░▒▓`, mirrored on the right). The badge silently falls back to plain whenever it wouldn't fit between the pane junction and the status indicator, so a narrow terminal never has it overwrite either.
- **`section_header_style()`** — `plain` (default) or `marker` (glyph-prefixed), applied consistently via one shared `draw_section_header` helper across all 5 header sites.
- **`metadata_style()`** — `aligned` (default, `Label : value` rows) or `inline` (condensed), scoped to the Context pane only.
- **`empty_state_style()`** — `plain` or `decorative`, via `draw_empty_state`, wired into every empty-state message in the app (station list, folder/search-empty, history, stats, context pane, folder manager, readd picker).
- **`dialog_title_align()`** — `left` (default) or `center`.

**Label alignment rule.** Metadata rows (Now Playing info block, Context pane) pad every label to the widest *actual* label via `ljust`, never to a hardcoded width. This used to be hardcoded spaces tuned for the default English labels, so any theme that relabeled fields (Cendre, Retro Radio) got a ragged colon column. The Now Playing width deliberately excludes the transient Sleep Timer label so rows don't shift sideways when a timer starts/stops. With default labels the output is byte-identical to the old hardcoded version (checked by diffing Classic/Cream/Reference before vs after).

### Known, deliberate gaps (not bugs — documented so nobody "fixes" them by accident)
- **`PAIR_BORDER` (the `border` color slot) is fully wired and resolvable in every theme, but nothing in the render code actually reads it.** Dialog borders currently use `PAIR_ACCENT`/`primary`; the main outer frame uses plain fg/bg. Changing this would visibly alter every existing theme's dialog borders — it needs its own deliberate pass, not a silent fix.
- **`decorative` only controls one thing**: the ASCII-title banner's shading tier. It does *not* control the empty-state flourish glyph (that was a real docstring mistake in an earlier draft of the `reference` theme, since corrected).
- **`idle_art` has three simultaneous conditions to ever render**: `now_playing_style` must be `dense` (not `minimal` — that style's docstring says "no metadata table, no idle art" on purpose), `current_station` must be `None` (never played anything yet *this session* — there's no "went idle again" reset), and the layout must not have fallen into the automatic compact mode a too-short terminal triggers. The validator emits an info-level note about this whenever a theme sets `idle_art`, and a warning specifically when a theme sets both `idle_art` and `now_playing_style = "minimal"` (i.e., art that can structurally never show).

### ASCII art / typography
- `render_ascii_word` / `render_ascii_word_raw` draw ASCII fonts (see registry above) with two-tone shading (`draw_shaded_ascii_row`), with per-theme glyph and font resolution (`resolve_ascii_font`, `glyph()`, `label()`) and fallback chains (`nerd → unicode → ascii`, via `cfg['glyph_mode']`, cycled from the Tools menu) for terminals with limited glyph support.

### Layout / canvas
- The whole layout (column widths, box sizes, art centering) was tuned by eye around a normal terminal (~171×39). Rather than stretching to fill an arbitrarily large terminal, the app draws onto a **capped canvas** (`MAX_CANVAS_W`, `create_canvas`) centered in the physical terminal — below the cap it fills the terminal exactly as before; above it, extra space becomes a calm margin, not stretched/sparse content.
- `handle_resize` recomputes canvas placement on terminal resize.
- **Rect-based panes (Layer 3 groundwork, 2026-10-09).** Panes no longer compute their own absolute coordinates. `Rect(x, y, w, h)` (with `.right` / `.bottom`) is the unit; `compute_frame_layout(h, w)` returns a `FrameLayout` (`split_x`, `stations`, `right`, `footer` rects) and `layout_right_column(body)` splits the right column into `workspace` / `divider_row` / `context` (plus the two compact flags). `draw_now_playing_tab(r)`, `draw_history_tab(r)`, `draw_stats_tab(r)` and `draw_context_pane(r)` draw into the rect they're handed, and `compute_now_playing_layout*()` / `now_playing_content_rows()` return rows **relative to the pane's top**, not screen rows. Still hardcoded, deliberately, until later steps: the one-third / two-thirds split itself, the border lines and their junction characters (`draw()` still draws them by hand from `split_x`), `station_list_start_row()`/`adjust_scroll()` (absolute rows), and the header/toast/HUD overlays. The refactor was verified zero-visual-change (see Testing). Planned next: a layout solver (`fixed` / `%` / `fill` weights / `auto` content-sized, with min/max) with today's layout as the default data, then a theme `[layout]` section made of named nodes, then automatic border junctions.

### App state / UI flow — `LofiApp`
- One large class driving the whole UI: station list, tabs (now playing / history / stats), wizards (add/edit station, folder create/manage, factory reset confirm, theme directory input), fuzzy search/filter (`fuzzy_score`, `update_filter`), scroll animation (`animate_scroll_to`), sleep timer, volume HUD.
- `draw()` is the single per-frame render entry point; `handle_input()` / `handle_wizard_input()` / `handle_theme_validator_input()` etc. are the corresponding per-mode input handlers, called from the main loop in `run()`.
- History/stats: each play session is tracked and finalized (`_finish_history_entry`), aggregated into `compute_stats()` and a per-station `get_station_history_stats()`.

### Testing approach (this project's own hard-won convention)
Beyond "John tests visually in his real terminal" (still true and still the final word), most of the theme-engine work above was verified with a **real pty + `pyte`** harness during development: actually spawning the app, feeding real keystrokes, and sampling *actual rendered cell colors/characters* from the parsed terminal output — not just a syntax check or a code-review "this looks right." This caught several bugs that a syntax check alone would have missed entirely:
- `curses.hline()`/`vline()` silently **truncate a literal Unicode character to its low byte** when passed via `ord(char)` — `"═"` became the letter `"P"`. Fixed by routing all border-drawing through `addstr()`/`addch()` instead, confirmed via direct testing that `addch()` accepts literal Unicode.
- `curses.color_pair(4) | curses.color_pair(2)` does **not** blend two colors — curses encodes the pair number in specific bits, and OR-ing two different pairs produces an arbitrary, unrelated pair number (this one silently rendered the "selected + playing" row as red instead of green+bold for an unknown amount of time before being caught).
- A raw `curses.hline(..., curses.ACS_HLINE, ...)` call (bypassing the app's own safe helper) can render as a literal `q` character instead of a dash, depending on locale — traced back to the app never calling `locale.setlocale()` at all. Fixed both the one stray call site and the missing locale call.
- `curses.color_pair()` (and other curses calls) **raise if called before `curses.initscr()` has run** — module-level constants that call it at import time will crash; they need to be deferred (`None` placeholders resolved inside `main()`).
- See the exact-color and TOML-gotcha entries above for two more real bugs (`can_change_color()` lying, readback having no teeth; `idle_art`/`ascii_title` silently nesting one table too deep) found the same way — by actually running the code, not by reading it.

**Layout regression gate (`tools/compare_apps.py`, harness in `tools/harness.py`, stub mpv in `tools/fake_mpv/`; see `tools/README.md`).** For layout work, 100 pty snapshots (5 builtin themes × 5 sizes from 60×15 to 191×41 × idle/playing/history/stats), plus extra states (debug overlay, sleep timer, search typing/no-results, density cycle, selection moves), are compared cell-for-cell — character, fg, bg, reverse, underline, and bold (bold is ignored in the station-list column only, because the now-playing pulse toggles it on a wall clock). Digits are masked since the clock/relative times change. The sandbox has no `mpv`, so the stub `mpv` (opens the IPC socket, answers `loadfile` with `start-file`/`playback-restart`) stands in for it. The gate compares two *versions of lofi.py* head-to-head (`git show HEAD:lofi.py > /tmp/before.py; python3 tools/compare_apps.py /tmp/before.py lofi.py`) rather than keeping stored golden files. Allow several minutes; run it in the background if your shell has a time limit. The debug overlay row range is timing-sensitive (log lines land at slightly different moments) — re-run before treating a debug-only diff as real.

When touching anything in the theming/rendering layer, the working pattern that's proven itself repeatedly: reproduce the reported problem in a real pty first (don't patch blind), fix, then run the *existing* regression suite of prior pty tests before considering it done — this codebase has a real history of a "fix" only handling the moderate case and missing the severe one (see the small-terminal Context-pane squeeze bug, which needed two passes: the first handled 28 rows fine but still lost real data at 15-18 rows).

### Theme engine build history — how we got to "Layer 1 / Layer 2" and why
Worth knowing if resuming theme work: early on, an external planning document (ChatGPT, pasted in by John) proposed a 26-phase "make everything themeable" mega-roadmap. Claude initially pushed back hard on scope (too much surface area for a single-file personal project with one user). Once John confirmed **public release is an actual goal** (not hypothetical), the plan was renegotiated into a layered structure that's since been mostly followed:
- **Layer 1 — finish the visual language.** Broken into four checkpointed sub-batches (not one big batch): **1a** density + semantic color-pair naming, **1b** Now Playing style variants + selection/status treatment, **1c** tabs + section headers + metadata layouts, **1d** dialogs (incl. padding) + empty states + footer. All four are done (see style-dimension list above).
- **Layer 2 — author-facing infrastructure.** In committed order: reference theme (done — see `reference` builtin / `reference.toml`, deliberately exhaustive, every field set to a non-default value so picking it *proves* each lever is wired), external TOML theme files (done), a minimal validator with auto-fix (done), preview mode (**not started**), docs (deliberately last, once the schema's proven stable — **not started**).
- **Explicitly deferred, on purpose, until after Layer 2 + stabilization + actual public release**: station packs (distributable/importable station collections — noted as a *separate track of work* (not a git branch — see the `main`-only rule below), not to be mixed into theme work, since the app's mpv-backed station abstraction already isn't YouTube-only), pack import/export, and any community ecosystem features.
- The "then stop, seriously" checkpoint from that plan: after Layer 1 + Layer 2 land, the intent was to dogfood the existing themes (Cendre, Retro Radio, Cream, Reference) and confirm the schema doesn't need to change shape *before* writing theme-author documentation or doing a public release — not to keep adding subsystems because a numbered list still has items on it.

## Conventions to keep
- **Single file.** Don't split `lofi.py` into modules unless explicitly asked — this is a deliberate personal-tool choice, not an oversight.
- **Stdlib only.** No new pip dependencies without asking first and explaining why in plain language.
- **Testing is visual and manual.** There is no automated test suite. John runs the app in his real terminal and reports visual discrepancies directly — he catches real bugs, not cosmetic nitpicks. Don't assume something works because the code "looks right"; flag anything that needs his eyes on a real terminal.
- **Don't touch working, unrelated code** while making a change — keep diffs scoped to the task at hand.
- **IPC over stdin, always**, for anything mpv-related — see the note in `MPVRemote`'s docstring above; this was a real, already-solved bug, don't reintroduce it.
